# 2026.270.1458 — fix(oci)!: ship a self-contained CUE schema (no schema-less plugin)

## Summary

Eradicate the schema-less plugin exception for `plugin-oci`, an ordered per-repo unit of the R5 cutover tracked in **opencharly/charly#712**.

The SDK contract (**opencharly/sdk#314**, landed) changed `sdk.BuildCapabilitiesWithRequires` to REJECT a `nil` schemaFS and an empty schema: every plugin MUST ship a non-empty, self-contained CUE schema served over `Describe` and spliced `base ++ plugin` at the host load gate. `plugin-oci` previously passed `nil` as the schemaFS and served an EMPTY `schema_cue`.

This change:
- Adds `candy/plugin-oci/schema/oci.cue` — a package-less, self-contained CUE doc schema defining `#OciPlugin` (the internal `verb: oci` op vocabulary (`merge`/`inspect-user`/`cache-push`/`cache-pull`)). It references no base def, so it compiles STANDALONE (the SDK's serve-side compile) and splices `base ++ plugin` at the host load gate.
- Embeds it with `//go:embed schema/oci.cue` → `var schemaFS embed.FS` and passes `schemaFS` to `sdk.NewMeta` instead of `nil`.
- Corrects the stale `plugin.go` / schema comments that claimed the plugin shipped no schema or that the schema was a `cue exp gengotypes` codegen source (it is NOT: the plugin declares no typed `plugin_input`, so there is no generated `params` package and no `cue exp gengotypes` artifact).
- Adds `schema_serve_test.go` with TWO tests: `TestNewMetaServesNonEmptySchema` (the served reply carries `#OciPlugin`) and `TestServedSchemaSplicesOntoHostBase` — which reproduces the REAL `base ++ plugin` splice the host load gate performs.

**Refs:** opencharly/charly#712
