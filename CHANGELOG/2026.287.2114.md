# 2026.287.2114 — feat(plugin-oci): the plugin-artifact push/pull legs, pinned to the published spec and sdk tags

## Summary

Two findings on this PR, both closed here: **the A2/R10 bed** (verdict `6173882810`) and **the
ingest leg's single-image `BLOCKS`** (`6176292129`).

**1. The cache pull now dispatches on the manifest media type.** `runCachePull` fetched with
`remote.Index(ref)` alone, so it could not fetch a **single-image** ref — the shape a registry
serves for an ordinary image tag, and the normal case for the images a registry has to serve. The
failure was hard, not a fallback:

```
pull <ref>: unexpected media type for ImageIndex():
  application/vnd.docker.distribution.manifest.v2+json; call Image() instead
```

One `remote.Get(ref)` now, dispatched on the descriptor's media type: an index/list takes the index
arm unchanged, and an image manifest is written as a layout whose top-level index carries that image
as its **one** root descriptor, annotated with the ref it was fetched from. That is the shape
`layout.AppendImage` owns, and it is what makes the layout readable by the same index-driven reader
on both arms — writing a single image without an index leaves `index.json` as a bare image
*manifest*, which has no index to read.

**⚑ The dispatch cannot be "try `ImageIndex`, fall back to `Image`", and that is the part worth
naming.** On an index ref `desc.Image()` does **not** fail — it silently resolves the index to
whichever single platform it picks — so a fall-back would quietly turn every index pull into a
one-platform image, and the bug would hide exactly where a registry serves an index. The media type
is therefore the key, and an unknown media type is a hard error naming what arrived.

**2. The change-class bed is authored here** (`check-plugin-artifact-transfer`), and it **composes
the venue** rather than discovering one: the operator-approved reference registry on
`127.0.0.1:5000` is brought up by the run, addressed by declaration, and torn down — `disposable:
true` is what authorizes the removal. This is the one way it differs from its sibling
(`plugin-cache`'s bed, which reads a pinned *public* upstream and says plainly that a public
upstream cannot be stopped): **this transport must PUSH, so it cannot use a public upstream at
all** — the registry is part of this capability's boundary rather than something that happened to be
running.

**Ownership.** This PR was taken over from `oci-plugin-lead` (`task-2`), which stopped at its
context budget with the leg unclaimed rather than half-built; the `TAKING OVER` is comment
`6178271399`, and my branch was cut from this PR's head (`838d726f`) so the previous session's

### The index arm's shape: a measured rebuttal, not an omission

The ingest leg's `BLOCKS` (`6176292129`) asked for **two** things: the media-type dispatch, and an
`AppendIndex` wrapper shape for the index arm. The first is implemented. **The second I reproduced,
measured, and am rebutting on the thread (comment `6178571651`) rather than implementing** — because
it breaks a contract this PR must keep:

```
$ go test ./... -run 'TestCacheTransportDeterministic' -count=1      # with the wrapper implemented
--- FAIL: TestCacheTransportDeterministic (0.03s)
    cache_transport_test.go:82: key "alpha" missing after transport round-trip

$ go test ./... -run 'TestCachePullIndexRefStaysAnIndex' -count=1     # the wrapper mutation
--- FAIL: TestCachePullIndexRefStaysAnIndex (0.03s)
    cache_transport_test.go:325: the pulled layout carries 1 entries, want the index's 2 (the index was collapsed)
```

`spec/cache`'s Layout resolves a named cache's entries **by reading `index.json`'s manifests and
matching a tag-derived key**, so a named ArtifactStore's `index.json` must carry its N named entry
descriptors directly. The wrapper replaces them with ONE root descriptor — which is what a *staged
single artifact* wants and what a *named cache layout* cannot survive. The missing key `alpha` **is**
that failure.

**And the requirement's premise does not hold for this shape, as the ingest's own committed code
states.** `plugin-cache`'s `stagedArtifactOf` (`candy/plugin-cache/cache_oci.go:275-316`) distinguishes
the two shapes **by measurement**, and its first branch is what this arm already writes — `index.json`'s
own bytes hashing to the reported digest — publishing those bytes as the top-level blob itself. So the
index arm's output is consumed correctly today, with no change on either side; the wrapper is a
preference for uniformity, and uniformity here costs the round-trip. Two assertions now pin it (the
mutations above are that reversal): `index.json`'s own bytes must hash to the reported digest, and
`index.json` must hold the index's N descriptors rather than 1.

**Still delivered:** the defect the ingest blocked on — a single-image ref being unfetchable — is
fixed, and the image arm uses the `AppendImage` shape exactly as asked.
