# 2026.266.1239 — feat(oci): cache-push / cache-pull — read and write a named cache to an OCI registry

## Summary

Adds the **registry transport** for the OCI-manifest-native cache: two new `verb:oci` ops — `cache-push` / `cache-pull` — that move a whole named `spec/cache.ArtifactStore` (landed in **opencharly/spec#148**) to and from an OCI registry, losslessly.

Because `spec/cache`'s ArtifactStore **is already a standard OCI Image Layout**, a named cache **is** an OCI image — its config blob carries entry validity, its layers the payloads, its index the named store. So the transport is a thin, lossless bridge with go-containerregistry:

- `cache-push` = `layout.ImageIndex()` → `remote.WriteIndex`
- `cache-pull` = `remote.Index` → `layout.Write`
- auth via `authn.DefaultKeychain` (docker config / credential helpers); `Insecure` permits a plain-HTTP local registry.

No bespoke format, no bespoke registry code — Docker cache principles (content-addressed blobs + a manifest/index entry point) reused verbatim, and the go-containerregistry stack stays HERE (this candy), never linked into spec or core.

**Files (6):** `cache_transport.go` (new: `CacheTransferRequest{Dir,Ref,Insecure}` + the two legs), `cache_transport_test.go` (new), `plugin.go` (OciOp dispatch gains `cache-push`/`cache-pull`), `candy/plugin-oci/charly.yml` (description + a deterministic `oci-cache-transport-present` ADE check), `go.mod` + `go.sum` (bump `spec` → `v0.2026266.1044` and `sdk` → `v0.2026266.1111` — the merged ArtifactStore + the sdk tag that consumes it).

Round-1 fixes folded in: the legs now return a REAL non-nil error on failure (never a success-shaped reply with `"error: …"` stuffed in `Digest`); `remoteOpts` takes no argument (plain-HTTP is selected by `name.Insecure` in `parseOpts`, not by the remote options); and the deterministic test now DRIVES the transport legs.
